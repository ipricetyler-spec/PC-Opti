# Legal and consumer release review

This is an engineering preparation checklist, not legal advice or legal clearance. It must be re-reviewed against then-current law, platform terms, and distribution plans before a public commercial release.

## Claims substantiation matrix

| Proposed claim | Current evidence | Allowed now | Required before stronger wording |
| --- | --- | --- | --- |
| “Reads supported Windows system state” | Native provider code, schema/errors, tests | Yes, qualified by support/permission limits | Windows integration matrix |
| “Changes are verified” | Post-action re-reads for supported mutable state | Yes, only per supported action | Isolated integration tests |
| “Rollback is available” | Exact state capture plus conflict checks | Only where the UI says available | Real rollback tests and upgrade compatibility |
| “Reclaims X bytes” | Sum of files successfully deleted | Only the measured result | Integration test for partial/locked-file behavior |
| “Boosts FPS” or percentage gain | None | No | Reproducible benchmark evidence for the exact scenario |
| “Reduces latency” | None | No | Defined endpoint/protocol and repeated before/after evidence |
| “Improves responsiveness/boot time” | None | No | Defined metric, controlled trials, and variance analysis |
| “Safe” without qualification | Not universal | No | Use concrete risk, scope, limitations, and rollback language instead |

README, screenshots, installer text, UI, release notes, store listings, and advertising are all representations. They must not exceed this matrix.

## Privacy

Use [PRIVACY_DATA_FLOW.md](PRIVACY_DATA_FLOW.md) as the technical inventory. Before public release add user-facing privacy terms covering local data, optional external provider, purpose, retention, deletion, user controls, and contact. Re-check the live provider terms used by the release.

## Security and supply chain

The engineering baseline follows the themes of NIST's final [Secure Software Development Framework 1.1](https://csrc.nist.gov/pubs/sp/800/218/final): prepare the organization, protect software, produce well-secured releases, and respond to vulnerabilities. NIST also lists SSDF 1.2 as draft, so this repository does not claim conformance to a draft.

Required evidence includes frozen Bun install, tests, type-check, build, vulnerability audit, CycloneDX inventory, artifact checksums, protected signing secrets, vulnerability reporting, and documented residual risk. SBOM output is an inventory aid; it is not a completed license or vulnerability opinion.

`bun run license:inventory` adds deterministic resolved-package and declared-license metadata from `bun.lock` plus installed manifests. Its JSON and Markdown outputs explicitly flag missing/platform-uninstalled metadata and exclude local absolute paths. See [THIRD_PARTY_INVENTORY.md](THIRD_PARTY_INVENTORY.md). This narrows the human review queue but does not satisfy it.

## Windows policy accuracy

Microsoft documents the `DisableWindowsConsumerFeatures` Group Policy mapping and states that the corresponding policy is edition-dependent, including no Pro support in the cited CSP table. See [Microsoft Experience Policy CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-experience). Dialed therefore labels the action Owner/experimental and must not promise an effect on unsupported editions.

- Installed component inventory: generated by `bun run sbom` (386 components in the current Windows evidence).

- Before public distribution, review every component's license/notice/redistribution obligations and Electron/Chromium notices. Automated identifiers can be missing or inaccurate.
- Do not bundle proprietary tuning databases, vendor binaries, copied optimizer code/UI, or material without redistribution rights.

### Clean-room kernel-driver program

Dialed currently bundles no polling-driver package. The owner selected a
first-party clean-room Dialed route instead of forward third-party redistribution.
No owner-supplied or downloaded third-party driver, INF, Setup executable,
implementation metadata, protocol, asset, branding or marketing may be copied,
translated, derived from or shipped in the Dialed implementation.

Before an external beta or commercial release, review the independent behavior
specification and complete provenance ledger for every source, sample,
specification and generated package member. Confirm the licenses and permitted
transformations, Dialed ownership, trademark/customer language, Windows
signing/catalog/Hardware Dev Center requirements, Memory Integrity and Secure Boot
compatibility, WHCP/HLK route, support scope and install/upgrade/restore/removal
evidence. A targeted IP review remains required; public availability or observable
behavior alone is not a derivative-work license. See
[DIALED_NATIVE_INPUT_STACK_HANDOFF.md](DIALED_NATIVE_INPUT_STACK_HANDOFF.md).

## Monetization

Current build: monetization is deferred. Public, consumer-premium and owner
profiles expose the same normal capabilities; the customer checkout/activation
surface is hidden and placeholder commerce configuration fails closed. Historical
trial, manual-code and checkout code is not a shipped entitlement or an active
billing claim.

If billing is enabled, run the following before publication:
- mirror returns and cancellation wording in the app, storefront, and README,
- point to the same support contact and support-SLA in all three surfaces,
- apply FTC Negative Option Rule and similar state-level review to the exact checkout flow,
- include a refund/cancellation section in release-facing pages before paid launch.

See also [SUPPORT_RETURNS_AND_TERMS.md](SUPPORT_RETURNS_AND_TERMS.md) and [DISTRIBUTION_LANDING_MARKETING_KIT.md](DISTRIBUTION_LANDING_MARKETING_KIT.md).

## Naming and IP

The owner selected **Dialed** on 2026-08-25 after a marketing-based naming round. Preliminary screening found an unrelated Windows audio-mixer project using `Dialed`, and `dialedpc.com` returned no Verisign `.com` RDAP registration record at the time of review. These observations do not establish availability or clearance. USPTO explains that comprehensive clearance includes confusingly similar sound, appearance, meaning, commercial impression, and related goods/services, not merely exact words; see [Federal trademark searching](https://www.uspto.gov/trademarks/search/federal-trademark-searching).

Before public promotion or material brand investment, search federal records, relevant state/common-law use, commercial web use, GitHub, package registries, app stores, domains, and social handles; include spelling/phonetic/visual variants and related software/services. Record results and obtain professional review. Do not claim legal clearance.

## Release sign-off

Human sign-off is required for legal terms, privacy notice, claims, license conclusions, name, pricing/monetization, signing purchase, and public publication.
